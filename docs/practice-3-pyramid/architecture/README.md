# Практика 3 (модуль 3) — Пирамида тестирования: карта системы

Артефакт №3: **карта системы СМП (6 диаграмм) + распределение тест-кейсов по уровням пирамиды**.

Диаграммы построены по white-box, а не перерисованы из документации. Основные источники:

- [`services/gateway/src/main/resources/application.yml`](../../../services/gateway/src/main/resources/application.yml) — маршруты Gateway;
- [`services/switch/src/main/java/com/processing/service/RouteService.java`](../../../services/switch/src/main/java/com/processing/service/RouteService.java) — оркестрация транзакции и откат;
- [`services/switch/src/main/java/com/processing/service/LoggerClient.java`](../../../services/switch/src/main/java/com/processing/service/LoggerClient.java) — асинхронная публикация;
- [`services/authorization/src/main/java/com/processing/authorization/services/AuthServiceImpl.java`](../../../services/authorization/src/main/java/com/processing/authorization/services/AuthServiceImpl.java) — логика авторизации;

- [`services/card-management/src/main/java/com/processing/cardmanagement/services/OutboxEventProcessorImpl.java`](../../../services/card-management/src/main/java/com/processing/cardmanagement/services/OutboxEventProcessorImpl.java) — outbox-публикация;

### Дополнительное расхождение по RabbitMQ retry/DLQ

`docker-compose.yaml` использует `rabbitmq:3.13-management`. В `RabbitMQConfig` главные очереди создаются через `QueueBuilder.durable(...)` без указания quorum-типа, а аргумент задан как `x-max-delivery=3`. Для такой classic-очереди нельзя считать этот аргумент работающим лимитом повторных доставок без подтверждения брокером.
