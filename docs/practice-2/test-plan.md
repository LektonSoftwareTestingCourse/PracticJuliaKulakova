# Тестовый план СМП

## 1. Область и подход

**Область:** обязательный функционал 11 сервисов СМП и инфраструктуры (PostgreSQL, RabbitMQ). Ядро (Authorization, Card Management) тестируется глубоко
, периферия (Gateway, Switch, симуляторы, Transaction Logger, Web Dashboard) - более общими решениями

**Подход:** риск-ориентированный

## 2. Критерии входа и выхода

### 2.1. Критерии входа 

- `docker compose up -d` поднимает все 11 сервисов, PostgreSQL и RabbitMQ без ошибок
- `docker compose ps` - все контейнеры в состоянии `Up (healthy)`
- сгенерировано не менее 100 тестовых карт (`POST /api/cards/generate`)
- зафиксированы версия сборки и `.env`, тестовые данные воспроизводимы
- e2e-набор из `services/e2e-tests` запускается и проходит на локальном стенде
- модель попарного тестирования сгенерирована: `pict/model.txt` → `cases.txt`, `pict/model-cms.txt` → `cases-cms.txt`
- известные ограничения зафиксированы заранее (неатомарность резервирования, rate-limit Gateway).

не проверена соответствующим уровнем.

## 3. Критерии приостановки и возобновления
   
### 3.1. Приостановка тестирования
**Тестирование приостанавливается, если:**   
   - критический сервис ядра недоступен (Authorization или Card Management не отвечают на health-check);
   - обнаружен блокирующий дефект, не позволяющий выполнять основные сценарии процессинговой цепочки (например, двойное списание, уход баланса в минус);
   - стенд не поднимается из-за нехватки ресурсов или занятых портов.
   
### 3.2. Возобновление тестирования
   **Тестирование возобновляется, когда:**  
   - сервисы восстановлены и проходят health-check;
   - блокирующий дефект исправлен и подтверждено исправление;
   - стенд поднят на чистой БД (`make clean` → `docker compose up -d` → генерация карт).

## 5. Инструменты, языки и фреймворки

- Попарное тестирование — Microsoft PICT 3.7.4 
- Документация — Markdown в docs/practice-2/.
- Язык и фреймворк сервисов ядра — Java 21 (Temurin), Spring Boot 3.4.1, Maven (многомодульная сборка).
- Автотесты — JUnit 5 (JUnit Jupiter) + Mockito + spring-boot-starter-test для unit-тестов ядра; TestNG 7.10.2 + REST Assured 5.4.0 + Awaitility + Hamcrest для e2e.
- Стенд — Docker Desktop, docker compose, Makefile (make run / status / logs / smoke); PostgreSQL 16-alpine, RabbitMQ 3.13-management.
- Качество и CI — Checkstyle, ESLint, GitHub Actions (JDK 21 Temurin, Node 24, кеш Maven).
- Наблюдаемость — Prometheus, Grafana, Loki, Promtail (профиль observability).
